# 09 — 常见问题与故障排查

## 通用与编辑器篇

**我必须熟练掌握 GDScript 才能使用这个模板吗？**  
不需要。超过 90% 的游戏开发工作（剧情、地图、怪物、地牢、道具、数值平衡）完全在可视化 Web 编辑器中完成。只有在您需要从零研发全新底层玩法机制（例如卡牌构筑或节奏小游戏）时才需要接触 GDScript。

**Web 编辑器需要 Node.js 或 npm 编译环境吗？**  
完全不需要。编辑器由纯 Python 标准库直接托管，Vue 3 通过 CDN 载入，秒级启动。

**在编辑器中保存了修改，但运行中的游戏里没有变化？**  
Godot 在游戏启动时加载 JSON 数据。在编辑器点击保存后，只需在 Godot 中重新运行 (▶️) 或在代码中调用 `Design.reload()` 即可。

**为什么有些 POI 在画面中央没有显示抠图的人物立绘？**  
在本模板中，许多 16:9 全景原画 (`assets/vn/bg/`) 已经将摊主或人物自然融入到了背景画卷之中。此时若没有单独配置透明的 `npc_<id>.png` 立绘，引擎 (`ViewPlace.gd`) 会清爽完整地展示背景画卷与文本框中的 Emoji 头像，避免画面突兀重叠。

## 数据与多语言篇

**多语言字段如何工作？如果我只想做单语言游戏呢？**  
游戏中所有面向玩家的文本均采用 7 语言字典格式（`zh`, `en`, `es`, `fr`, `it`, `de`, `ja`）。如果您只想制作中文或英文游戏，只需在对应语言字段填入内容即可；底层引擎自带安全容错回退机制，缺失其他语言翻译时不会发生报错。

**玩家的游玩存档保存在哪里？**  
保存在用户数据沙盒目录中（`user://save_slot_*.json`），由 `SaveManager.gd` 独立负责读写，与 `data/` 中的游戏设计工程数据严格隔离。
