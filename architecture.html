System Design

Taos Game Maker Architecture

Taos Game Maker is engineered around a clean, decoupled three-tier architecture. It bridges human-readable JSON schemas, a visual web-based studio suite, and a high-performance Godot 4 client engine.

The 3-Tier Data Pipeline

│                    TIER 1: DATA LAYER                       │

Tier 1: Pure Data-Driven Core

Unlike monolithic game projects where game balance, dialogues, and coordinates are hardcoded into engine scripts, Taos Game Maker stores 100% of game definitions in isolated JSON files:

  • data/world.json: Overworld grid coordinates, terrain codes, weather, and object placement.
  • data/dungeons/: Grid layouts, modular wall orientations, doors, chests, and boss spawn triggers.
  • data/enemies.json: Combat stats, elemental resistances, turn speeds, drops, and AI ability pools.
  • data/skills.json: Target scopes, MP/AP costs, status affliction chances, and visual FX keys.
  • data/npcs/: Branching dialogue trees, speaker portraits, choices, and condition evaluations.
  • data/quests.json: Objectives, step tracking, journal entries, and reward allocations.

Tier 2: The Local Web Studio Layer

The studio suite is hosted locally on your machine via a lightweight Python server (editor/serve.py). It exposes a rich, responsive interface with over 45 dedicated managers:

World & Dungeon Suite

Real-time map painting, terrain brush, entity placement, dungeon modular piece architect, and interactive 3D walkthrough simulator.

Narrative & Quest Suite

Node-based visual dialogue graph editor, VN asset previewer, NPC presence managers, and branching quest wizards.

Combat & Systems Suite

Turn-based sandbox simulator, skill synergy balancer, profession progression trees, and world transform event managers.

Validation & QA Suite

Automated data integrity validator that scans for broken IDs, missing assets, circular quest triggers, and orphan nodes.

Tier 3: Godot 4 Client Runtime Engine

The Godot 4 project is structured around modular Autoload singletons and isolated View controllers:

Core Engine Autoloads

  • Design Manager: Loads and caches JSON databases, provides unified accessor APIs, and hot-reloads data during development.
  • GlobalState: Manages runtime session data, party members, inventory, quest progress, story flags, and persistence.
  • SoundManager: Handles adaptive background music (BGM), environmental ambience, and spatial sound effects (SFX).
  • Juice: Centralized juice system delivering screen shake, chromatic aberration flashes, floating combat text, and haptic feedback.
  • Localization (i18n): High-performance multi-language lookup supporting dynamic runtime language swapping.

Engine View Subsystems

The gameplay transitions smoothly between specialized view controllers based on context:

View Controller Gameplay Mode Key Features
ViewWorld 3D Overworld Exploration Grid movement, biomes, dynamic camera, weather effects, POI triggers, transport vehicles.
ViewDungeon 1st-Person Dungeon Crawler 90° discrete grid turning, wall mesh instancing, torch lighting, chests, door locks.
ViewCombat Turn-Based Tactical Battle Timeline queue, active skill selection, status animations, floating combat numbers, enemy AI.
ViewDialogue / ViewPlace Visual Novel & City Exploration Character portraits, branching choices, city markets, craft workshops, quest journals.
ViewGather & ViewTransport Resource Gathering & Trade Farming nodes, resource processing, caravan transport routes, inventory management.

Extensibility & Modding

Because the engine is 100% decoupled from the data, you can create entirely new campaigns, standalone games, or mod expansions simply by swapping or editing the data/ folder.

Diseño de Arquitectura

Arquitectura de Taos Game Maker

Taos Game Maker está diseñado sobre una arquitectura desacoplada en tres capas. Conecta esquemas JSON legibles por humanos, un estudio web visual local y el motor cliente de alto rendimiento en Godot 4.

Capa 1: Núcleo 100% Data-Driven

A diferencia de los proyectos monolíticos donde las fórmulas de balance, los textos y las coordenadas están incrustados en scripts, Taos Game Maker almacena la totalidad de las definiciones del juego en archivos JSON desacoplados:

  • data/world.json: Coordenadas del overworld, códigos de terreno, climatología y colocación de entidades.
  • data/dungeons/: Estructuras de rejilla, piezas modulares de pared, puertas, cofres y salas de jefes.
  • data/enemies.json: Estadísticas de combate, afinidades elementales, velocidades de turno, tablas de botín y rutinas de IA.
  • data/skills.json: Tipos de objetivo, costes de MP/PA, probabilidades de estado alterado y claves de FX visuales.
  • data/npcs/: Grafos de diálogo ramificados, retratos de personajes, elecciones y evaluación de condiciones.
  • data/quests.json: Objetivos, seguimiento de pasos, entradas de diario y asignación de recompensas.

Capa 2: Estudio Web Visual Local

La suite de edición se ejecuta localmente en tu ordenador mediante un servidor Python ligero (editor/serve.py). Ofrece una interfaz completa y moderna con más de 45 herramientas especializadas:

Mundo y Mazmorras

Pintado de mapas en tiempo real, pincel de terrenos, colocación de entidades, arquitectura de piezas de mazmorra y simulador de recorrido 3D interactivo.

Narrativa y Misiones

Editor visual de grafos de diálogo por nodos, visor de assets de novela visual, gestor de presencia de NPCs y asistentes de misiones ramificadas.

Combate y Sistemas

Simulador de batallas por turnos, calibrador de sinergias de habilidades, árboles de clases y profesiones, y gestor de eventos de mundo.

Validación y QA

Validador automático de integridad referencial que comprueba IDs rotos, assets inexistentes, bucles en misiones y nodos huérfanos.

Capa 3: Runtime Cliente en Godot 4

El proyecto de Godot 4 está estructurado en torno a singletons Autoload modulares y controladores de vista especializados:

Autoloads Centrales del Motor

  • Design Manager: Carga y mantiene en memoria las bases de datos JSON, expone APIs unificadas y permite recargar datos durante el desarrollo.
  • GlobalState: Controla el estado de la sesión, grupo de héroes, inventario, progreso de misiones, flags de historia y guardado de partida.
  • AudioManager: Gestiona la música de fondo ambiental adaptativa (BGM), pistas de batalla y efectos de sonido posicionales (SFX).
  • Juice: Sistema centralizado de respuesta visual y háptica: sacudidas de pantalla, aberración cromática, números flotantes y destellos.
  • Localization (i18n): Sistema de traducción de alto rendimiento compatible con cambio dinámico de idioma en caliente.

Subsistemas de Vistas Especializadas

El flujo de juego transiciona de forma fluida entre vistas según el contexto:

Controlador de Vista Modo de Juego Funcionalidades Clave
ViewWorld Exploración de Overworld 3D Movimiento por casillas, biomas dinámicos, cámara cenital, niebla de guerra, POIs y vehículos.
ViewDungeon Crawler de Mazmorras en 1ª Persona Giros discretos de 90°, generación modular de mallas 3D, antorchas dinámicas, trampas y cofres.
ViewCombat Combate Táctico por Turnos Cola de turnos ATB, selección de habilidades, estados alterados, animaciones y rutinas de IA.
ViewDialogue / ViewPlace Novela Visual y Ciudades Retratos expresivos, ramas de decisión, tiendas, talleres de forja y diario de misiones.
ViewGather & ViewTransport Recolección y Rutas de Comercio Nodos de extracción, refinamiento de recursos, rutas de caravanas y gestión de almacén.

Extensibilidad y Modding

Al estar el motor completamente desacoplado de los datos, puedes crear campañas totalmente nuevas, juegos independientes o mods completos simplemente editando o reemplazando la carpeta data/.
